# [Доменная маршрутизация для OpenWrt 25+](README.detailed.md#доменная-маршрутизация-для-openwrt-25)

Проект направляет выбранные домены через TUN-интерфейс **sing-box** и поддерживает OpenWrt 25 или новее.

[подробнее](README.detailed.md#доменная-маршрутизация-для-openwrt-25)

## [Что изменилось в OpenWrt 25](README.detailed.md#что-изменилось-в-openwrt-25)

Установка использует `apk`, firewall4/nftables и списки dnsmasq `nfset`. Поддерживается автономный установщик для sing-box; старые версии OpenWrt и другие типы туннелей не поддерживаются.

[подробнее](README.detailed.md#что-изменилось-в-openwrt-25)

## [Установка](README.detailed.md#установка)

Выполните команду ниже **на роутере**, выберите список **Russia inside** (по умолчанию), **Russia outside** или **Ukraine** и настройте sing-box. После установки или переустановки **обязательно перезагрузите роутер**. По умолчанию при исчезновении маршрута туннеля IPv4 может пойти напрямую, а IPv6 всегда разрешён напрямую.

```sh
wget -O /tmp/getdomains-install.sh https://raw.githubusercontent.com/overm/domain-routing-openwrt/master/getdomains-install.sh && sh /tmp/getdomains-install.sh
```

[подробнее](README.detailed.md#установка)

### [Дополнительные параметры](README.detailed.md#дополнительные-параметры)

Добавляйте нужные флаги после имени скрипта; при установке из другой ветки или коммита задайте общий источник файлов через `GETDOMAINS_SCRIPT_BASE_URL`, как показано в полной инструкции.

[подробнее](README.detailed.md#дополнительные-параметры)

#### [`--offload medium|strict|disable`](README.detailed.md#--offload-mediumstrictdisable)

Режим `medium` по умолчанию ускоряет подходящие прямые IPv4 NAT-соединения; после изменения сетевой политики нужны Save & Apply и перезагрузка. Режим `strict` применяет поддерживаемые изменения с кратковременным отключением проводных LAN/WAN и разрывом IPv4-соединений, а `disable` отключает ускорение. Аппаратное ускорение экспериментально и ограничено профилем Xiaomi AX3000T / MT7981, OpenWrt 25.12.5; `--kill-switch` отключает его целиком, а установка и смена режима требуют перезагрузки.

[подробнее](README.detailed.md#--offload-mediumstrictdisable)

#### [`--no-icanhazip`](README.detailed.md#--no-icanhazip)

Отключает автоматическое добавление `icanhazip.com` в доменные наборы. Без этого флага команда `curl -4 icanhazip.com` проверяет внешний IPv4 через туннель.

[подробнее](README.detailed.md#--no-icanhazip)

#### [`--ipv6-deny`](README.detailed.md#--ipv6-deny)

Отклоняет IPv6-соединения к выбранным доменам от клиентов LAN и самого роутера, чтобы клиент мог попробовать IPv4. Домены без рабочего IPv4 станут недоступны.

[подробнее](README.detailed.md#--ipv6-deny)

#### [`--kill-switch`](README.detailed.md#--kill-switch)

Запрещает прямой IPv4 для маркированного трафика, если в таблице `vpn` нет маршрута; состояние удалённого прокси не проверяется. Для запрета обоих прямых путей используйте вместе с `--ipv6-deny`. Повторный запуск без этих флагов удаляет соответствующие ранее созданные правила.

[подробнее](README.detailed.md#--kill-switch)

#### [`--wdns`](README.detailed.md#--wdns)

Опция `--wdns DNS_IPV4` задаёт DNS-сервер через туннель для выбранных доменов и создаёт DHCP-тег `wdns` для отдельных клиентов. Клиент с этим тегом обращается к DNS напрямую, поэтому его запросы обходят локальные записи и не пополняют доменные наборы; для доменной маршрутизации используйте DNS роутера. Повторная установка без флага сохраняет существующий тег.

[подробнее](README.detailed.md#--wdns)

## [Раздельный DNS и LuCI](README.detailed.md#раздельный-dns-и-luci)

С WDNS выбранные домены разрешаются через DNS туннеля, остальные — через DNS WAN; без WDNS все внешние запросы используют DNS WAN. Локальные записи и ручные **DNS → IP Sets** управляются через LuCI, а Save & Apply запускает обновление правил. Текущие отслеживаемые IPv4-соединения сохраняют выбранный маршрут при изменениях DNS и списков.

[подробнее](README.detailed.md#раздельный-dns-и-luci)

## [Типичные сценарии в LuCI](README.detailed.md#типичные-сценарии-в-luci)

Сначала закрепите IPv4-адрес клиента в **Network → DHCP and DNS → Static Leases**. Затем выберите нужный сценарий ниже и примените настройки через **Save & Apply**.

[подробнее](README.detailed.md#типичные-сценарии-в-luci)

### [Весь IPv4-трафик клиента через туннель](README.detailed.md#весь-ipv4-трафик-клиента-через-туннель)

В **Network → Routing → IPv4 Rules** добавьте правило для IPv4-адреса клиента с маской `/32`, таблицей `vpn` и приоритетом `70`. Для запрета прямого IPv4 при исчезновении маршрута добавьте правило `unreachable` для того же источника с приоритетом `71`; IPv6 настраивается отдельно. Перед удалением проекта удалите эти ручные правила.

[подробнее](README.detailed.md#весь-ipv4-трафик-клиента-через-туннель)

### [DNS-сервер из туннеля для конкретного клиента](README.detailed.md#dns-сервер-из-туннеля-для-конкретного-клиента)

После установки с `--wdns DNS_IPV4` добавьте тег `wdns` в поле **Set Tag** статической аренды клиента и обновите его DHCP-аренду. Тег сообщает DNS-сервер, но не направляет весь трафик клиента в туннель и не запрещает сторонний DNS или DoH.

[подробнее](README.detailed.md#dns-сервер-из-туннеля-для-конкретного-клиента)

### [Весь IPv4-трафик клиента только напрямую](README.detailed.md#весь-ipv4-трафик-клиента-только-напрямую)

В **Network → Firewall → Traffic Rules** добавьте IPv4-адрес клиента с префиксом `!` и без `/32` в **Source address** правила `mark_domains`. Этот сценарий несовместим с полной маршрутизацией того же клиента через туннель. При `--ipv6-deny` для прямого IPv6 дополнительно исключите MAC-адрес клиента с префиксом `!` в **Source MAC address** правила `block_domains6`.

[подробнее](README.detailed.md#весь-ipv4-трафик-клиента-только-напрямую)

## [Проверка](README.detailed.md#проверка)

Запустите `getdomains-check --lang=ru` на роутере для проверки туннеля, DNS, firewall и маршрутизации, в том числе после применения настроек LuCI.

[подробнее](README.detailed.md#проверка)

## [Удаление](README.detailed.md#удаление)

Команда `getdomains-uninstall` удаляет правила и службы проекта, сохраняя пакет и конфигурацию sing-box, ручные записи LuCI и статические DHCP-аренды. Если работает владелец аппаратной таблицы, удаление завершится автоматической перезагрузкой: заранее сохраните остальные изменения.

[подробнее](README.detailed.md#удаление)

## [Конфигурация sing-box](README.detailed.md#конфигурация-sing-box)

Заполните параметры `CHANGE_ME` в `/etc/sing-box/config.json` и проверьте файл командой `sing-box check -c /etc/sing-box/config.json`; существующий конфиг сохраняется. Для защиты от петли TUN оставьте `route.auto_detect_interface: true` либо настройте эквивалентную привязку интерфейса. При некорректной конфигурации установщик пропускает перезапуск sing-box и начальную загрузку списка.

[подробнее](README.detailed.md#конфигурация-sing-box)

## [Обновление списков](README.detailed.md#обновление-списков)

Список обновляется ежедневно в 04:00 через `tun0`; при ошибке остаётся предыдущая проверенная версия, а последний источник сохраняется для загрузки роутера. После настройки туннеля обновление можно запустить вручную командой `/etc/init.d/getdomains refresh`. Политика зависит от IP, изученных через DNS роутера: внешний DNS, DoH и кеш клиента могут её обойти, а общий IP CDN — затронуть другие домены.

[подробнее](README.detailed.md#обновление-списков)
