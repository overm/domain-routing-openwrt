# Доменная маршрутизация для OpenWrt 25+

Проект направляет выбранные домены через TUN-интерфейс **sing-box**. Требуется
OpenWrt 25 или новее. Старые выпуски OpenWrt, а также
WireGuard, AmneziaWG, OpenVPN и tun2socks больше не поддерживаются.

## Что изменилось в OpenWrt 25

В OpenWrt 25 пакетный менеджер `opkg` заменён на **`apk`**, а не на `apt` из
Debian/Ubuntu. Поэтому установщик использует `apk update` и `apk add`. Проект
теперь рассчитан только на firewall4/nftables
и списки dnsmasq `nfset`; код совместимости со старым ipset удалён.

Команда запуска загружает скрипт через входящий в BusyBox `wget`. Автономный
установщик до внесения изменений проверяет версию OpenWrt и наличие `apk`. Он
устанавливает `curl`, `sing-box`, `dnsmasq-full`, `ip-full` и `nano`,
создаёт правила для `tun0`, сохраняет команды диагностики и удаления в
`/usr/bin` и не перезаписывает существующий `/etc/sing-box/config.json`. В конце
установки скрипт предлагает сразу открыть этот конфиг в `nano`, проверяет его и,
если конфигурация корректна, перезапускает sing-box после применения настроек
сети.

Поддерживается только автономный установщик; Ansible-роль удалена.

## Установка

```sh
wget -O /tmp/getdomains-install.sh https://raw.githubusercontent.com/overm/domain-routing-openwrt/master/getdomains-install.sh && sh /tmp/getdomains-install.sh
```

Во время установки выберите один доменный список: **Russia inside** (по
умолчанию), **Russia outside** или **Ukraine**.

Без дополнительных флагов IPv4 выбранных доменов идёт через туннель, но при
исчезновении маршрута через `tun0` может продолжить путь напрямую. IPv6 не
маршрутизируется в туннель и также разрешён напрямую. Это режим fail-open.

### Дополнительные параметры

#### `--no-icanhazip`

По умолчанию установщик добавляет `icanhazip.com` в набор `vpn_domains`, чтобы
проверка внешнего IPv4 выполнялась через туннель. Правило
`mark_local_domains` маркирует совпадающий трафик самого роутера в
`mangle_output`, поэтому для однозначной проверки используйте
`curl -4 icanhazip.com`. Без `-4` curl может выбрать разрешённый напрямую IPv6.
При включённом `--ipv6-deny` домен добавляется также в `vpn_domains6`. Эта
привязка сохраняется как
отдельная секция `vpn_icanhazip` в `/etc/config/dhcp` и отображается в LuCI на
вкладке **DNS → IP Sets**; в загружаемый файл `/tmp/dnsmasq.d/domains.lst`
установщик её не дописывает. Чтобы развернуть конфигурацию без этого домена,
запустите установщик с флагом `--no-icanhazip`:

```sh
sh /tmp/getdomains-install.sh --no-icanhazip
```

#### `--ipv6-deny`

По умолчанию ответы AAAA для выбранных доменов разрешены напрямую через IPv6.
Флаг `--ipv6-deny` создаёт набор `vpn_domains6`; dnsmasq помещает в него AAAA,
а firewall отклоняет новые совпадающие соединения из LAN и от самого роутера.
`REJECT` возвращает ошибку сразу, поэтому клиент с поддержкой IPv4 обычно может
быстро попробовать адрес A. Если у домена нет рабочего IPv4, соединение не
будет установлено:

```sh
sh /tmp/getdomains-install.sh --ipv6-deny
```

#### `--kill-switch`

По умолчанию отсутствие маршрута в таблице `vpn` не останавливает обработку
policy rules, и маркированный IPv4 может уйти через основной маршрут. Флаг
`--kill-switch` добавляет следующее правило `unreachable` для mark `0x1`:
сначала правило с приоритетом 100 ищет маршрут в таблице `vpn`, затем правило с
приоритетом 110 запрещает прямой IPv4, если маршрут не найден.

```sh
sh /tmp/getdomains-install.sh --kill-switch
```

Это не healthcheck. Если `tun0` и маршрут существуют, но удалённый прокси не
отвечает, трафик может зависнуть в туннеле; автоматического переключения или
блокировки по состоянию прокси нет. Сам по себе `--kill-switch` не запрещает
IPv6. Для запрета обоих прямых путей используйте флаги вместе:

```sh
sh /tmp/getdomains-install.sh --kill-switch --ipv6-deny
```

| Параметры | IPv4 при отсутствии маршрута `vpn` | IPv6 выбранных доменов |
| --- | --- | --- |
| без флагов | напрямую | напрямую |
| `--kill-switch` | запрещён | напрямую |
| `--ipv6-deny` | напрямую | запрещён |
| оба флага | запрещён | запрещён |

Повторный запуск установщика применяет указанный режим: отсутствие
`--kill-switch` или `--ipv6-deny` удаляет ранее созданные правила именно этой
опции.

#### `--wdns`

Флаг `--wdns DNS_IPV4` создаёт DHCP-тег `wdns` и задаёт для него DNS-сервер,
доступный внутри туннеля. Например:

```sh
sh /tmp/getdomains-install.sh --wdns 172.16.250.2
```

Чтобы клиент со статической арендой получил этот DNS вместе с фиксированным
IPv4-адресом, добавьте тег к соответствующей секции `host` в
`/etc/config/dhcp` (или выберите тег `wdns` для static lease в LuCI):

```text
list tag 'wdns'
```

```sh
getdomains-check --lang=ru
```

## Удаление

```sh
getdomains-uninstall
```

Скрипт удаления убирает правила доменной маршрутизации, но намеренно сохраняет
пакет и конфигурацию sing-box. Обе команды загружаются установщиком и остаются
доступны локально после очистки каталога `/tmp`; при удалении они также удаляются.

## Конфигурация sing-box

Если `/etc/sing-box/config.json` отсутствует, установщик создаст
Shadowsocks-шаблон с параметрами `CHANGE_ME`. Заполните их во время установки:
при некорректной конфигурации sing-box не будет перезапущен, а первоначальная
загрузка списка будет пропущена. Существующий конфиг не перезаписывается.

Позже отредактировать и проверить конфигурацию можно командами:

```sh
nano /etc/sing-box/config.json
sing-box check -c /etc/sing-box/config.json
service sing-box restart
```

Ниже приведён отдельный базовый пример, который использует основное подключение
роутера в качестве выхода (`outbound`). Это не шаблон, создаваемый установщиком.
Пример можно взять за основу и изменить блок `outbounds` под свою конфигурацию.

```json
{
  "log": {
    "level": "warning"
  },
  "inbounds": [
    {
      "type": "tun",
      "tag": "tun-in",
      "interface_name": "tun0",
      "address": [
        "172.16.250.1/30"
      ],
      "auto_route": false,
      "stack": "system"
    }
  ],
  "outbounds": [
    {
      "type": "direct",
      "tag": "direct-out"
    }
  ],
  "route": {
    "auto_detect_interface": true,
    "final": "direct-out"
  }
}
```

Для TUN-конфигурации оставьте `route.auto_detect_interface: true` либо задайте
эквивалентный глобальный `route.default_interface`. Вариант с
`outbound.bind_interface` безопасен, только если привязан каждый outbound,
который может быть выбран для TUN-трафика; диагностика консервативно требует
привязку у всех outbound. Без одного из этих механизмов трафик может вернуться
в `tun0` и образовать петлю. Эту настройку нужно проверить и в собственном
конфиге.


## Обновление списков

Обновление списков выполняется транзакционно: данные сначала загружаются во
временный файл, проверяются ограничение размера, ожидаемый формат и синтаксис
dnsmasq, и только после успешной проверки активный файл атомарно заменяется.
Для `--ipv6-deny` при обработке к каждой записи добавляется набор
`vpn_domains6`. Блокировка исключает одновременный запуск из cron и вручную,
при ошибке сети или проверки продолжает работать предыдущий список, а службы
перезапускаются только при реальном изменении данных. Обновление запускается
ежедневно в 04:00 и загружает список через `tun0`.

`vpn_domains` и, при включённом `--ipv6-deny`, `vpn_domains6` хранят отдельные
IP-адреса с timeout два дня и лимитом 65536 элементов. Когда новое
соединение из LAN или от самого роутера обращается к уже известному адресу,
nftables обновляет его timeout до двух дней. Проверка членства выполняется до
операции `update`, поэтому трафик к неизвестному адресу не может добавить его в
набор. Ограничение `ct state new` исключает запись в набор для каждого пакета;
неиспользуемые адреса автоматически удаляются. Одно непрерывное соединение не
продлевает timeout после своего первого пакета: для продления должно начаться
новое соединение к тому же адресу.

Доменные адреса намеренно хранятся только в оперативной памяти: активный файл
находится в `/tmp/dnsmasq.d/domains.lst`, а IPv4/IPv6-адреса — в nft-наборах.
После перезагрузки они появятся снова лишь после загрузки списка и DNS-запросов
через локальный dnsmasq. До этого уже закешированный клиентом IP может не попасть
под `--kill-switch` или `--ipv6-deny`. Обратный риск связан с CDN: один IP может
обслуживать несколько имён, и попадание адреса в набор по домену из списка
повлияет также на обращение к домену не из списка. При недоступном маршруте
`vpn` kill switch заблокирует такой общий IPv4; `--ipv6-deny` аналогично
отклоняет общий IPv6. Обновление timeout выполняется по IP, а не по имени:
новые соединения к общему CDN-адресу могут продлевать его присутствие, даже
если они относятся к другому домену. Поэтому популярный общий адрес способен
оставаться в наборе дольше двух дней; при `--ipv6-deny` его продлевают в том
числе повторные отклонённые попытки соединения.

Правила действуют только на адреса, которые локальный dnsmasq получил при
разрешении имён. Внешний DNS, DNS over HTTPS и обращения к IP напрямую не
создают новые элементы наборов и могут обойти доменную политику. Обращение к IP,
уже находящемуся в наборе, обновляет его timeout.

Устройство регистрируется в netifd как неуправляемый логический интерфейс
`singbox_tun`. Для локального процесса `curl`, привязанного к `tun0`, создаётся
отдельное policy rule через `singbox_tun`: поле `out` в UCI ссылается на
логический интерфейс OpenWrt, а не непосредственно на имя Linux-устройства.
TUN-зона отклоняет новый входящий трафик к роутеру и новые перенаправления из
неё. Системный TUN-стек sing-box создаёт для клиентского соединения новый TCP
поток, который conntrack ещё не считает `ESTABLISHED`. Отдельное узкое правило
принимает его только от TUN-peer `172.16.250.2` к адресу `172.16.250.1` и
стандартному диапазону локальных ephemeral-портов `32768-60999`. Порты SSH,
LuCI и DNS оно не открывает. Перед каждой загрузкой скрипт до 30 секунд ждёт
появления интерфейса и успешного разрешения имени источника, поэтому короткий
перерыв DNS при применении сетевых настроек не приводит к немедленной ошибке.
Источник списка должен быть доступен через настроенный туннель.
Перед первым обновлением настройте и запустите sing-box. Если установщик не смог
выполнить начальную загрузку, после запуска туннеля выполните
`/etc/init.d/getdomains start` вручную.
