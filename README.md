# [Доменная маршрутизация для OpenWrt 25+](README.detailed.md#доменная-маршрутизация-для-openwrt-25)
Проект направляет выбранные домены через TUN-интерфейс **sing-box** и поддерживает OpenWrt 25 или новее.

## [Что изменилось в OpenWrt 25](README.detailed.md#что-изменилось-в-openwrt-25)
Установка использует `apk`, firewall4/nftables и списки dnsmasq `nfset`. Поддерживается автономный установщик для sing-box; старые версии OpenWrt и другие типы туннелей не поддерживаются. [подробнее](README.detailed.md#что-изменилось-в-openwrt-25)

## [Установка](README.detailed.md#установка)
Подключитесь к роутеру по SSH и выполните команду ниже **на роутере**, выберите список **Russia inside** (по умолчанию), **Russia outside** или **Ukraine** и настройте sing-box. После установки или переустановки **обязательно перезагрузите роутер**. По умолчанию при исчезновении маршрута туннеля IPv4 может пойти напрямую, а IPv6 всегда разрешён напрямую. [подробнее](README.detailed.md#установка)
```sh
wget -O /tmp/getdomains-install.sh https://raw.githubusercontent.com/overm/domain-routing-openwrt/master/getdomains-install.sh && sh /tmp/getdomains-install.sh
```

### [Дополнительные параметры](README.detailed.md#дополнительные-параметры)

Добавляйте нужные флаги после имени скрипта.
[подробнее](README.detailed.md#дополнительные-параметры)

#### [`--offload medium|strict|disable`](README.detailed.md#--offload-mediumstrictdisable)

Режим `medium` по умолчанию ускоряет подходящие прямые IPv4 NAT-соединения; после изменения сетевой политики нужны Save & Apply и **перезагрузка**. Режим `strict` применяет поддерживаемые изменения с кратковременным отключением проводных LAN/WAN и разрывом IPv4-соединений, а `disable` отключает ускорение. Аппаратное ускорение экспериментально и не гарантируется на всех роутерах; `--kill-switch` отключает его целиком, а смена режима требует переустановки и перезагрузки.
На других совместимых роутерах MT7981/MT7986 установщик предлагает экспериментальный `medium` только после явного согласия (`y` или `yes`, по умолчанию — отказ). Отказ или несовместимость продолжают установку без ускорения; `strict` остаётся только для проверенного профиля Xiaomi AX3000T. Требования к ядру, nftables и схеме портов сохраняются.
[подробнее](README.detailed.md#--offload-mediumstrictdisable)

#### [`--no-icanhazip`](README.detailed.md#--no-icanhazip)

По умолчанию дополнительно добавлен домен `icanhazip.com`, чтобы проверить туннель командой `curl -4 icanhazip.com`. Эта опция отключает его автоматическое добавление в доменные наборы. [подробнее](README.detailed.md#--no-icanhazip)

#### [`--ipv6-deny`](README.detailed.md#--ipv6-deny)

Отклоняет IPv6-соединения к выбранным доменам от клиентов LAN и самого роутера, чтобы клиент мог попробовать IPv4. Домены без рабочего IPv4 станут недоступны. [подробнее](README.detailed.md#--ipv6-deny)

#### [`--kill-switch`](README.detailed.md#--kill-switch)

В случае проблем с туннелем запрещает прямые соединения для доменов из списков. Для запрета также и IPv6 используйте флаг вместе с `--ipv6-deny`. Переустановка без этих флагов удаляет соответствующие ранее созданные правила. [подробнее](README.detailed.md#--kill-switch)

#### [`--wdns`](README.detailed.md#--wdns)

Опция `--wdns DNS_IPV4` задаёт DNS-сервер через туннель и создаёт DHCP-тег `wdns`, который можно проставлять для отдельных клиентов. Клиент с этим тегом обращается к DNS напрямую, поэтому его запросы обходят логику доменной маршрутизации и не пополняют доменные наборы. Для таких клиентов предполагается полная маршрутизация IPv4 через туннель: [Весь IPv4-трафик клиента через туннель](README.md#весь-ipv4-трафик-клиента-через-туннель). [подробнее](README.detailed.md#--wdns)

## [Раздельный DNS и LuCI](README.detailed.md#раздельный-dns-и-luci)

Для клиентов, использующих DNS роутера, с WDNS домены из списка разрешаются через указанный DNS в туннеле, остальные — через DNS WAN; без WDNS все внешние запросы используют DNS WAN. Локальные записи и ручные **DNS → IP Sets** управляются через LuCI. [подробнее](README.detailed.md#раздельный-dns-и-luci)

## [Свои наборы доменов](README.detailed.md#свои-наборы-доменов)

Свои домены добавляйте на вкладке **DNS → IP Sets**, выбирая набор `vpn_domains`, а при `--ipv6-deny` также `vpn_domains6`. По умолчанию там уже добавлен `icanhazip.com`, если установка выполнена без `--no-icanhazip`.

## [Типичные сценарии в LuCI](README.detailed.md#типичные-сценарии-в-luci)

Сначала закрепите за клиентом IPv4-адрес в **Network → DHCP and DNS → Static Leases**. Затем выберите один из сценариев ниже или совместимую комбинацию сценариев.

### [Весь IPv4-трафик клиента через туннель](README.detailed.md#весь-ipv4-трафик-клиента-через-туннель)

В **Network → Routing → IPv4 Rules** добавьте правило для IPv4-адреса клиента с маской `/32`, таблицей `vpn` и приоритетом `70`. Для запрета прямого IPv4 (kill-switch) при исчезновении маршрута добавьте правило `unreachable` для того же источника с приоритетом `71`; IPv6 настраивается отдельно. Перед удалением проекта удалите эти ручные правила. [подробнее](README.detailed.md#весь-ipv4-трафик-клиента-через-туннель)

### [DNS-сервер из туннеля для конкретного клиента](README.detailed.md#dns-сервер-из-туннеля-для-конкретного-клиента)

После установки с `--wdns DNS_IPV4` добавьте тег `wdns` в поле **Set Tag** статической аренды клиента и обновите его DHCP-аренду. Тег сообщает DNS-сервер, но не направляет весь трафик клиента в туннель и не запрещает сторонний DNS или DoH. [подробнее](README.detailed.md#dns-сервер-из-туннеля-для-конкретного-клиента)

### [Весь IPv4-трафик клиента только напрямую](README.detailed.md#весь-ipv4-трафик-клиента-только-напрямую)

В **Network → Firewall → Traffic Rules** добавьте IPv4-адрес клиента с префиксом `!` и без `/32` в **Source address** правила `mark_domains`. Этот сценарий несовместим с полной маршрутизацией того же клиента через туннель. При `--ipv6-deny` для прямого IPv6 дополнительно исключите MAC-адрес клиента с префиксом `!` в **Source MAC address** правила `block_domains6`. [подробнее](README.detailed.md#весь-ipv4-трафик-клиента-только-напрямую)

## [Проверка](README.detailed.md#проверка)

Запустите команду ниже на роутере для проверки туннеля, DNS, firewall и маршрутизации, в том числе после применения настроек LuCI. [подробнее](README.detailed.md#проверка)
```sh
getdomains-check --lang=ru
```

## [Удаление](README.detailed.md#удаление)

Команда удаляет правила и службы проекта, сохраняя пакет и конфигурацию sing-box, ручные записи LuCI и статические DHCP-аренды. Если работает владелец аппаратной таблицы, удаление завершится автоматической перезагрузкой: заранее сохраните остальные изменения. [подробнее](README.detailed.md#удаление)
```sh
getdomains-uninstall
```

## [Конфигурация sing-box](README.detailed.md#конфигурация-sing-box)

Во время установки будет предложено отредактировать конфиг sing-box в `/etc/sing-box/config.json`. При некорректной конфигурации установщик пропускает перезапуск sing-box и начальную загрузку списка. Позже можно самостоятельно отредактировать конфиг и проверьте файл командой `sing-box check -c /etc/sing-box/config.json`. Учтите рекомендации, а также можно использовать пример по ссылке [подробнее](README.detailed.md#конфигурация-sing-box)


## [Обновление списков](README.detailed.md#обновление-списков)

Список обновляется ежедневно в 04:00 через `tun0`; при ошибке остаётся предыдущая проверенная версия, а последний источник сохраняется для загрузки роутера. После настройки туннеля обновление можно запустить вручную командой ниже. Политика опирается на IP-адреса, изученные через DNS роутера: сторонний DNS, DoH и кеш клиента могут её обойти, а общие IP-адреса CDN — затронуть домены вне списка. [подробнее](README.detailed.md#обновление-списков)
```sh
/etc/init.d/getdomains refresh
```
